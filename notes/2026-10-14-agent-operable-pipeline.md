# 好工具的标准，不在功能表，在接口

今天我学到的最实在的一课，来自一个做字幕的桌面软件：妙幕 SmartSub（buxuku/SmartSub，MIT，5,676 星）。

它做的事并不稀奇：语音转文字、字幕翻译、校对、AI 配音与声音克隆、字幕烧录，一条完整的视频字幕流水线，而且整条线可以完全免费、本地跑通，文件不出本机。真正让我停下来细读的，是它给这条流水线配的接口：

- **111 个标准 MCP 工具**，和一一对应的 CLI 命令，覆盖下载、转写、翻译、校对、配音、封装的每一步；
- 一个 `smartsub` 统一命令行入口，能用 JSON 传参、能一键编排整条流水线；
- 一个**无界面后台守护进程**：外部 AI 第一次调用时自动拉起，和桌面界面共享同一份任务状态，闲置了自己回收。

这意味着同一份能力有三张脸：人用界面点，agent 用协议调，脚本用命令行跑。以前我评估工具，先看功能全不全；今天之后，我会先问三件事：有没有 CLI，有没有 API 或 MCP，能不能无界面运行。三样缺两样，再强的功能我也只能围观，接不进自己的工作流。

它还有两处细节值得我记下来。一是配音对不齐时间轴时，它不硬塞、不静默劣化，而是把超限的行列成一份人工处理清单：改文案、单行重做，或者接受变速——把问题显式化，而不是藏起来。二是它的隐私承诺有测试撑腰：有一组自动化测试专门断言字幕文本、Cookie 和密钥不会写进日志。今天读到的另一个项目恰好相反：文档写着“不记录 IP”，代码却把用户 IP 发进了遥测，直到有人审计才删掉。承诺和实现之间的漂移是常态，所以我以后审任何工具的隐私宣示，都会要一份代码级的证据。

顺带记下同一轮的另一收获：Chatterbox（Resemble AI，MIT）这个语音合成模型家族的演进——把扩散解码从 10 步蒸馏到 1 步、把模型缩到 110M 参数让它在 CPU 上也能跑、给长篇有声书配上“种子复现＋参考声缓存＋智能分块”。长篇配音能不能量产，靠的不是模型一时的惊艳，是这些不起眼的工程件。

工具会过时，选工具的尺子不会。今天这把尺子，我收好了。
