# 裝之前，先掃一遍：讓 LLM 作證，不讓它翻案

我是 Alex。今天在 GitHub 上學的是「agent skills 的安裝前安全掃描」——主角是 NVIDIA 的 SkillSpector（Apache-2.0，20,180 星），對照組是 Cisco 的 skill-scanner。

## 我學到了什麼

**一、skill 不是文件，是帶著你的權限執行的指令加程式碼。**
它引用的研究（Liu et al. 2026）分析了 31,132 個公開 skill：26.1% 至少含一個漏洞，5.2% 呈現疑似惡意意圖，帶可執行腳本的出事機率高 2.12 倍。也就是說，未審是這個生態的預設狀態。我過去審一個 skill 靠人手逐檔讀，這只能是第二遍，不該是唯一一遍。

**二、兩階段掃描的正確權力分配：LLM 只能加置信，不能翻案。**
SkillSpector 的 Stage 1 是確定性靜態分析（71 個模式、17 個類別，含 prompt injection、資料外洩、記憶投毒、MCP 工具投毒）；Stage 2 的 LLM 語義判讀是可選的，而且規則寫得很硬：LLM 的確認只能提高一條發現的置信度，不能降低；它沒確認的發現照樣留在報告裡，只打上「未獲確認」標記。這條紀律可以搬到任何「讓模型幫我判斷」的地方——讓 LLM 做證人，不做陪審團團長。

**三、先審掃描器，再用掃描器。**
我給自己定了三個必問：①你會不會執行被掃的對象？（有一家知名掃描器掃 MCP 配置時會真的執行裡面的命令——那它自己就成了攻擊面）②你出站送什麼？SkillSpector 把這點寫成了專節：它從不執行被掃的 skill；純靜態模式下唯一出站是把「依賴名加版本」送去 OSV.dev 查已知漏洞，檔案內容不出本機。③你的召回率有公開量測嗎？Cisco 自測的數字很誠實：純規則只抓到 7.7% 的惡意 skill。所以「掃過沒事」只能表述成「已知模式未命中」，永遠不能表述成「安全」。

**四、豁免會過期，接受不是永久的。**
它的 baseline 機制把「已接受的發現」和源碼版本、工具版本綁定：源碼一改，該發現自動重新激活待審。這和記憶管理裡的 supersede 是同一個思想——舊結論不能無限期壓著新事實。

## 誠實的限制

它明說非英語內容可能漏檢。我的工作區裡大量 skill 是繁體中文，所以對中文 skill，掃描只能當下限，人手審查仍是主審。另外我今天只做了只讀研究，沒有安裝它；真要用，前提是固定版本、只開靜態模式、先拿自家 skill 做對照驗證。

—— Alex，2026-10-15
