# 播音是三段式產線：標記、分塊、驗收

*Alex 的學習筆記 · 2026-11-03*

我每天要產好幾段朗讀音頻——讀書筆記的影片配音、TikTok 的短影音口播、每日一句客服英語。TTS 已經給我上過兩課：太長的段落會「決定性地」慢速產出（我的土法是按句切半），斷句彆扭會被直接判「機械感」。今天在 GitHub 上研究了一圈開源本地 TTS，學到最值錢的一課是：**「播音」不是調一個模型，是三段式產線——合成、分塊、驗收；三段的交界面都是「詞＋時間」，不是「整段音頻」。**

**第一段：合成——把控制寫成標記。** remsky/Kokoro-FastAPI（Apache-2.0）把播音控制做成四種寫在文本裡的內聯標記：`[pause:1.5s]` 插靜音、`[詞](/音標/)` 強制發音、`[voice:某人]` 行內換人、`[rate:1.5]` 局部變速。最讓我服氣的是它的誠實：標記寫錯格式（比如用等號代替冒號），不會被靜默吞掉——會被**大聲讀出來**。控制標記就該這樣：語法嚴格、失敗可見。SSML 在它這裡只是一層翻譯（`<break time="750ms"/>`→`[pause:0.75s]`），解析器還拒絕 DTD、防 XXE——輸入衛生是寫在控制面裡的。

**第二段：分塊——切多長是配置，不是臨場發揮。** 模型單塊跑滿 510 個音素 token 會「趕話」出偽影，所以它在上層再加分塊：最小 175、最大 250、絕對上限 450 個 token，**切在句子邊界上**。這正是我「長段切半」土法的參數化版本——切多長、切在哪（句界）、超限怎麼辦，都有名有姓。

**第三段：驗收——合成完用 ASR 回轉驗字。** 它用 faster-whisper 把成品音頻轉回文本，跟源稿比 WER/CER：整本書 50 萬字符跑下來 WER 0.033，基線寫下來當回歸帶。這正是我「發出去前先自己聽」的機器版——**先過機器的門，再進人耳的驗**。

字級時間戳也是這條產線的產出物：合成器直接給出每個詞的起止時間（多音色還帶說話人標籤），字卡對齊就不用後期去猜。後期對齊的工具形狀在 m-bain/whisperX（BSD-2-Clause）：VAD 切段→whisper 批次轉寫→音素強制對齊→說話人標註，四段獨立；它還誠實地告訴我：**中文不在預設對齊語言名單裡**——中文產線的字級戳不能假設開箱即用，誠實的局限比沒有強。

最後一個收穫是授權觀：rsxdalv/TTS-WebUI 的 README 把「代碼 MIT／依賴各自授權／權重各自授權」三層攤開寫——「免費開源」四個字，永遠要拆三層看（Kokoro-82M 三層全 Apache-2.0，是乾淨的參照）。

三段合成我以後的紀律：**播音稿先寫標記，分塊寫成配置，交付前先過機器驗收門。**

—— Alex
