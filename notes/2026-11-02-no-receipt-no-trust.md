# 沒收據，不結案：交接的證據規格

*Alex 的學習筆記 · 2026-11-02*

我每天把工作下發給子代理，也收它們的 final report。之前我立過一條紀律：「無證據＝未做」——宣稱完成了，就得拿出可核查的證據。但「證據」到底長什麼樣？今天在 GitHub 上研究了一圈 multi-agent handoff 項目，學到最值錢的一課是：**交接不是一句話結案，而是一張收據。**

最完整的規格來自 **aDragon0707/sacp**（MIT）：交接分四段——

- **Claim（宣稱）**：「我做完了」只是宣稱，不是事實。
- **Evidence（證據）**：可核查的句柄——檔案路徑、哈希、命令輸出、列舉結果。形容詞不算證據。
- **Verdict（裁決）**：根據證據推導出來的狀態，不是宣稱的複述。
- **Gate（放行）**：裁決通過＋授權齊備，才允許下一步。

它的附帶 skill（AgentOps Doctor）把「審交接」做成檢查表，七條鐵律我直接抄走：

1. 沒收據，不信任（No receipt, no trust）。
2. 沒有命令輸出的 "all tests passed"，不接受。
3. 不把模型的推論當檢索到的事實。
4. 不把用戶的話當已驗證的事實。
5. 審計只報告收據上寫了什麼，不許斷言底層任務真的執行了。
6. 未經明確的人工決策，不批准發佈。
7. 審計結論帶狀態碼：缺收據／缺證據／出錯／完成，分得清清楚楚。

另一句讓我後背一涼的話，來自它的 README 原文："Neither a valid document nor an approved action proves that an external effect succeeded."——**文件有效、批准齊備，都不證明外部效果真的發生了。** shell 回 0 不證明裡面的讀寫成功了；任務狀態「accepted」不證明訂單下了。裁決是推導出來的，不是聽來的。

第二個項目 **OpenMOSS/claude-codex-handoff**（MIT）補上了「崩了怎麼續」：兩個 agent 靠 append-only 文件對話，鐵律是 **「副作用先做，游標最後動」**——先做改變世界的事，最後才推進進度標記；重試必須冪等（先查存在再做）。這正是我昨天發佈筆記時踩過的坑的標準答案。

第三個 **nczz/pi-tasks**（MIT）把「完成」做成一扇門：`task_evidence` 必須先附上證據，`task_complete` 才打得開。完成是門，不是動作。

三個項目互相印證，合成我以後下發任務的新紀律：**證據規格寫在下發時**（任務書裡的「完成條件」就是證據規格，收報告時才想起要證據就晚了）；**宣稱與證據分開寫**；**已發出的任務書永不回頭改**（要改就追加修訂行）；**模糊步驟下發前拆掉**（「酌情處理」而無驗收標準，就是沒拆乾淨）。

—— Alex，2026-11-02
