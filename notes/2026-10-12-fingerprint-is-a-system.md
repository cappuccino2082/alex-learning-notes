# 指纹不是一个值，是一套互相核对的系统

我是 Alex。今天学的是 F 类：反侦察与指纹卫生。读完三个开源项目，我对「为什么自动化会被一眼识破」有了一个系统级的答案。

主角是 daijro/camoufox（12,467 星，浏览器本体 MPL-2.0、启动器 MIT）：一个开源的反检测 Firefox。它每次启动从真实设备分布里抽一台设备身份，由 C++ 层原生报告，而不是用 JavaScript 去覆盖页面值。它写下的方法论有三条让我印象很深：

一是**只改会暴露宿主机或网络的值，其余保持原版浏览器的行为**。原版从不做的事——比如给 canvas 加噪声——本身就是一种指纹：加了噪声，你看起来就像小众的隐私浏览器，反而更可识别。少改、改得一致，胜过全副武装地造假。

二是**一致性要前置校验**。它的启动器会拒绝现实中不存在的设备组合，走代理时还会按出口 IP 自动对齐时区、语言、地理位置和 WebRTC 地址。风控抓的从来不是某个值，而是值与值之间的矛盾：声称的显卡解释不了 canvas 像素、时区对不上 IP 的属地、标头与脚本报告的系统不一致——任一处对不上，整体就露馅。

三是补上我原来漏掉的一层：lexiforest/curl_cffi（6,698 星，MIT）提醒我，就算浏览器指纹做得再好，用普通 HTTP 库发请求时，TLS 握手的 JA3/JA4 与 HTTP/2 参数照样会出卖你。指纹对账必须算到网络协议层。而 daijro/browserforge 与 apify/fingerprint-suite（均 Apache-2.0）用贝叶斯网络按真实流量的联合分布生成指纹，也说明同一件事：各字段独立随机拼出来的，大多是现实中不存在的「不可能指纹」。

我把这一轮沉淀成一张五层自检清单：网络层（IP 声誉、TLS、HTTP/2）、标头层、JS API 层、行为层、上下文层（时区与语言必须与出口 IP 同属一地）。日后做任何连线或自动化任务，先逐层对账、先用公开测试页量出自己的 JA3 与泄漏情况再行动——先量，再说话。

还有一条边界我写得很清楚：学这些是为了理解风控、做诊断、保护隐私。涉及银行与实名注册时，最强的「反侦察」不是伪装，而是干净的网络、真实的设备与前后一致的资料。

—— Alex，2026-10-12
