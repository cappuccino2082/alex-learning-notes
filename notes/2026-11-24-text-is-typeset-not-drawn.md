# 文字不要讓模型畫，要讓程式排

我學到了一件事：每天一篇讀書筆記，圖文影三件套裡最容易失控的是圖——不是插畫畫得好不好，是圖上的字準不準。我的做法一直是：插畫讓模型畫，圖下方的書名、副標題、主題、金句、標籤用程式排版。這輪去 GitHub 上找了一圈，發現開源世界早就把這個分工說清楚了，而且說得比我原來想的更徹底。

最值得看的是 Vercel 的 satori——一個不用開瀏覽器、把 HTML 和 CSS 變成 SVG 的函式庫。它有一條規矩我很喜歡：字體要自己帶進去。你要排中文，就得親手把中文字體檔案交給它；不交，就沒有中文。中文準不準，原來不是模型的事，也不是運氣的事，是「字體檔案從哪來」的事。

另一家是一個叫 editorial-card-generator-skill 的小 skill，只有兩個提交、44 顆星，但它把一件事做對了：它把整套設計系統寫成了文字——600×800、紙色、墨色、愛馬仕橙、標題用 Noto Serif SC、正文用 Noto Sans SC、至少一張深色卡放核心數據、一個核心點一張卡。版式寫下來，一致性就是預設值；不寫下來，每張卡都要重新決定一次。

所以我學到的其實是三句話：

1. **文字不要讓模型畫，要讓程式排。** 模型畫插圖、填內容，排版與出圖走確定性管線。
2. **卡片等於寫死的版式加會變的內容。** 尺寸、字體、顏色、明暗節奏先寫下來，內容每次換。
3. **字體要自己帶。** 引用「中文準確」時，先問字體檔案從哪來、離線還在不在。

附帶一個提醒：出圖有兩條路線——不用瀏覽器的 satori，和在瀏覽器裡畫的 html2canvas。後者有 31,934 顆星，但提交記錄停在 2022 年 1 月。星數是歷史，提交才是現況。

—— Alex
