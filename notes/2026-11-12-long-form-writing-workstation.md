# 長文寫作工作站的三件套

*Alex 的學習筆記 · 2026-11-12*

我每天寫長文——讀書筆記、研究報告——然後把它切成短版、標題鉤子、口播稿、社群貼文。改寫的守則我上週已經寫下來了（改寫不發明），但有一個問題我一直沒認真問過：長文本身是在哪裡寫的？手稿住在哪裡、跨章節怎麼找得到、AI 幫寫的時候範圍誰來控、改壞了怎麼回得去？

這一輪我在 GitHub 上找答案，最有收穫的是一個昨天剛發新版的終端工具：[blackInkhaven](https://github.com/vulogov/blackInkhaven)（★28，Rust，昨天發 3.21.0）。

## 我學到了什麼

**長文寫作工作站有三件套，缺一件就會退回聊天框加複製貼上：**

1. **手稿是純文字檔案。** Inkhaven 把一本書存成一層層的 `.typ` 檔案（書 → 章 → 節 → 段落），詮釋資料另外存在本地資料庫，只管階層與搜尋。正文永遠是看得懂、能 diff、能版本控管的文字。我的筆記本來就是這個形狀（Markdown 檔案），看到它被做成正式架構，我才確定這不是將就，是選擇。

2. **語義索引在本地。** 它用 fastembed 加 HNSW 在本機算向量搜尋，搜「燈塔熄滅的那一刻」找得到沒寫過這幾個字的段落。3.21.0 還修了一個誠實的細節：小專案（兩萬個向量以下）改走精確搜尋，因為 HNSW 會漏最近鄰。跨篇找「以前寫過的同一主張」，正確形狀是索引，不是搜尋框。

3. **AI 的範圍是可以點的。** 每次推論要先選三個開關：scope（選取／段落／小節／章／全書）、mode（只查本地 RAG 或放開通識）、destination（取代／插入／置頂／置底／複製／只改文法）。AI 是範圍可控的共同作者，不是聊天框。

零預算路徑也是真的：內建六個模型供應商，設 `llm.default: "ollama"` 就走本地模型；3.21.0 還允許每個供應商自訂 `base_url`，任何 OpenAI 相容端點一行設定就接上。README 也明寫：用外部供應商就沒有隱私可言，提示詞按對方條款上傳——要隱私就走本地。

## 兩個附帶的教訓

**描述不等於倉庫。** 同一輪有個搜尋結果寫著「Planner-Worker-Evaluator 架構、零幻覺輸出」，打開一看：倉庫是空的，一個檔案都沒有。查核順序應該是倉庫非空 → 最近提交 → README 原文 → 授權原文，描述只是廣告。

**授權不一致本身就是信號。** Inkhaven 根目錄的 LICENSE 是 Unlicense（公有領域奉獻），但它的安全文件內文卻寫 Apache-2.0 AND MIT 雙授權——而且那份文件自述停在 1.2.15 版，已經過期兩個大版本。引用或改寫前要先釐清，不能寫成已確定的授權；文件新鮮度也是可信度的一部分。

## 誠實的邊界

Inkhaven 不是我今天能直接接上的工具：手稿格式是 Typst 不是 Markdown，中文支援也還沒核實（預設只列英文與俄文）。它是我長文寫作紀律的參考實現，不是即插即用的零件。同一輪的另一家「內容改寫管線」則因為依賴兩個付費 API（轉錄與生成都要 key）被我排除了，只留下三個方法論碎片：輸出格式先驗證再交件、截斷要保住句子邊界、失敗要有狀態。
